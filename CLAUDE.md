# HealthLog Backend — правила работы

## Агентная система

**Для всех задач разработки — немедленно запускать агента `orchestrator`**, не выполнять задачу самостоятельно. Оркестратор управляет командой из 13 субагентов (архитектор, медицинские эксперты, разработчик, QA и др.) и ведёт задачу от ветки до деплоя.

Исключения — выполнять напрямую, без orchestrator:
- Вопросы о коде: объяснить, найти, прочитать
- Срочные однострочные хотфиксы с явным указанием пользователя

**ВАЖНО:** любая задача разработки — редактирование файлов, коммиты, PR — только через оркестратора. Самостоятельное выполнение запрещено, даже если кажется что задача простая.

## Ветки

- Перед началом любой задачи проверить наличие активной невмерженной ветки (`git branch -a`, `gh pr list`).
- Если активной ветки нет — создать новую от `master`:
  ```bash
  git checkout master && git pull origin master
  git checkout -b feat/<название>   # или fix/, test/, chore/
  ```
- Одна задача — одна ветка. Изменения напрямую в `master` запрещены.

## Деплой

- После открытия PR — дождаться прохождения CI, затем **смержить PR без ожидания команды пользователя**: `gh pr merge <N> --squash`.
- После мержа — следить за деплоем: `gh run list --repo Oilg/HealthLog --limit 3`. Убедиться что деплой прошёл успешно (`conclusion: success`).
- Подтвердить деплой на сервере: проверить что сервис перезапустился и новый код применён.

## Тесты

- После добавления нового кода — добавить тесты. Тесты не опциональны.
- Структура: `tests/unit/` для unit-тестов, `tests/` для интеграционных.
